# Venera-Max

> 一个以 [VeneraX](https://github.com/Kyosee/VeneraX)（其上游为 [venera-app/venera](https://github.com/venera-app/venera)）为基础、
> **按我们自己的阅读习惯深度改装的漫画阅读器**。
>
> 这个仓库里的每一处改动都是我们自己做的：**加了什么功能、修了什么问题，全部写在下面**。
> 不是上游的说明，也不用上游的名字来讲这个故事。

- 平台：iOS（主要）/ Android / 桌面（沿用上游的多平台结构）
- 核心漫画源：**栗子漫画（lizimh）** —— 源仓库见 [Walter498/Walter](https://github.com/Walter498/Walter)
- 编译：`push` 到 `main` → GitHub Actions 工作流 `venerax-ios` 自动编译（约 12 分钟）→ 在该次运行的 **Artifacts** 里取 IPA

---

## 一、我们加了什么

### 章节面板（详情页）
- **清单 / 封面预览双模式**：清单是传统的章节按钮；封面预览是 5 列封面网格（用于挑"从哪一话开始看"）
- **真正的收起 / 展开**：收起时固定 3 行，下方就是「显示全部 (N)」按钮；展开才全量渲染
- **封面懒加载**：源没给章节封面时，按需向源取该话第一页当封面；同一话只请求一次并做内存缓存
- **正序 / 倒序**切换，历史已读章节以浅色 + 角标标识
- 章节重复项过滤（同一话多份时只渲染一份，但下标不乱，下载/进度不受影响）

### 阅读器
- **连续阅读（上下滚）** 与 **画廊翻页（左右）** 双模式，连续模式支持无缝拼接多章
- **上滑切下一章 / 下滑切上一章**：滑到章末继续上滑，跨过阈值即切章；底部圆环进度条实时显示离阈值还有多远
- **该距离可调**：阅读设定 →「上滑切换下一章距离（像素）」，40~400，默认 160（数字越小越省力）
- **触觉反馈**：跨过阈值切换章节时中震一下；滑到章末/章首、出现「上方/下方还有章节」提示时轻震一下
- **单点召唤工具栏 + 800ms 静止判定**：只有"真的滑动过并且停稳 800ms"才认；刚进漫画属于静止状态，第一下点击立刻出上下栏
- **自定义点击区域**：四边可分别设为「上一页 / 下一页 / 无」（无 = 交给召唤工具栏）
- **边缘返回手势**：屏幕左侧约 0.5cm 内右滑返回
- **自动阅读**：连续模式按设定速度平滑滚动，画廊模式按间隔带动画翻页；双击停止
- **章节选择器 / 下载**、**章节内嵌评论区**（源支持时在章末展示）
- **15 秒载入看门狗**：卡住时给错误 + 重试，而不是无限转圈

### 首页 / 探索 / 搜索
- 首页一级分页内联：**首页 / 更新 / 排行**（可由来源自适应）
- 首页推荐（4×2 网格 + 更多页）、周期更新（按星期的 tab）、跨来源条目合并
- 首页"刷新"按钮 = 清掉首页缓存重新拉；缓存策略是"完整才存"（避免半截数据被缓存）
- 探索页支持**来源内容首页**（源自带首页数据时直接用）
- 分类页：筛选 chips + 多选标签（AND 取交集）+ 来源切换
- 搜索：同名作品聚合分组，按**真实章节数**排序（后台 `loadInfo` 补齐）

### 详情页
- 上次阅读时间 + **前 3 个阅读位置**（上上次、上上上次）直接点进对应位置
- 合集详情：封面 / 章节视图切换，合集内成员可改名排序
- 「清除此漫画缓存」（磁盘图片缓存 + 源页面缓存 + 内存图缓存）
- 评论内嵌加载（只暴露评论按钮的源也能直接看到评论）

### 收藏 / 社区
- 收藏改为书架式：**收藏 / 书单 / 足迹** 三个 tab，文件夹选择、排序（多种排序方式 + 上次阅读时间）、详细/简洁两种卡片
- 社区：栗子社区只读接入（动态流 / 文章 / 评论）

### 外观
- **Material 3 / 液态玻璃（Liquid Glass）**可切换；玻璃风格覆盖底部栏、卡片、对话框、阅读器工具栏、搜索框

### 下载 / 缓存
- 下载页多选、单页失败跳过继续（不会因为一页坏图卡死整个任务）
- 所有图片请求（阅读 + 下载 + 封面）统一带上源要求的 UA

### 漫画源（lizimh / 栗子）
- **多域名池 + 自动回退**：主域名挂了自动换线，记住可用域名，另有「线路测速」按钮并行测延迟
- **官方图片顺序**：人工上传的章节，文件名编号 ≠ 阅读顺序；用官方 `chapter/v3` 接口（只需 JWT）取正确顺序，失败才回退数字推导
- **页数探测加速**：一次并行扫描 + 补扫空缺，两轮出结果（早期是多轮二分）
- **第一张存在的页**：有些日漫章节不是从第 1 页开始（第 1~4 页 404），先从前往后找出真正存在的第一页当起点
- **不许删页**：只有"连续两页都不存在"才承认到末页；单页探测失败绝不删（以前会因此整章错位）
- 图片 403/404 时自动重新解析页面清单再重试

### 设置
- 阅读设定数值化：自动滚动速度、自动翻页间隔、鼠标滚动速度、翻页后置中、页面间隙、**上滑切换下一章距离**
- **此漫画特定设定** 与 **装置特定设定**：同一项设置可只对某部漫画 / 某台设备生效
- 设置搜索、备份与同步（WebDAV，沿用上游）

### CI
- GitHub Actions 自动编译 iOS，构建日志提交回仓库（`ios build log [skip ci]`），IPA 放 Artifacts

## 二、我们修了什么（症状 → 原因 → 处理）

| 症状 | 原因 | 处理 |
|---|---|---|
| 封面预览模式下章节区下方一大片空白，滑半天才到「显示全部」 | 网格 `childCount` 是全部章节数，被"收起"的格子只是返回空 Widget，**格子照样占位** | 收起时改用固定尺寸的 `Wrap`（外面套死高度的 sliver），高度物理上就只有 3 行；展开才用网格 |
| 封面预览模式根本没有「显示全部」按钮 | 按钮被 `if (!gridMode)` 限制住了 | 两种模式都渲染，并按封面模式自己的门槛（15 格）判断是否需要按钮 |
| 刚进漫画，第一下点屏幕出不来上下栏（明明是静止的） | 进页面时**程序自己做的初始定位**（还原上次阅读位置）以及图片陆续载入造成的位移都会发 `ScrollEnd`，把"刚停手"时间戳刷成当下 → 800ms 静止判定把第一次点击吃掉 | 只有**用户自己的拖动**（`dragDetails != null`）才算滚动，程式化滚动一律不写时间戳 |
| 上滑切下一章 / 下滑切上一章没有任何震动反馈 | 代码里**从来没有**实现过这个触觉反馈 | 跨过阈值时 `mediumImpact`，提示出现时 `selectionClick` |
| 章节页数不对（156 页只显示 153 页），越到后面越乱 | 末页探测失败时把该页从清单里删掉 → 缺页之后全部错位 | 只有连续两页确认不存在才承认末页；探测失败不删页；快取校验同规则（旧错误快取自动失效重探） |
| 日漫某章一直卡在「1/N」转圈 | 该章页码不从 1 开始（第 1~4 页 404），我们从第 1 页生成清单 | 推完末页后往前找出第一张真正存在的页当起点 |
| 有些章节图片顺序和官方 App 完全不同 | 人工上传章节的档名编号 ≠ 阅读顺序 | 以官方接口的 `pics` 数组为准（失败才用数字推导） |
| 栗子域名 `ai.qsmm.fun` 挂了，探索/详情全打不开 | 域名写死在源里 | 域名池 + 自动回退 + 记住可用域名 + 测速按钮 |
| 章节封面一片空白 | JS 桥缺 `chapterCovers` 字段；改用 `Image.network` 又不带 UA 被图床 403 | 补字段；封面统一走 App 的图片载入器（带 UA） |
| 排行榜前三名角标崩溃 | 用了 0-based 下标取颜色（`colors[-1]`） | 修正下标 |
| 详情页偶发崩溃 | `previousPositions` 返回可变列表，排序时改了内部状态 | 返回副本再排序 |
| 本地漫画目录被删/改名后崩溃（`PathNotFoundException`） | 目录列表没做保护 | 包一层目录检查，给干净的错误提示 |
| 下载卡住不动 | 单页失败会拖死整个任务 | 单项失败跳过继续 |
| 「清除缓存」清不掉源接口的旧数据 | 只清了图片缓存，没清 HTTP 响应缓存 | 一并清 `NetworkCacheManager`，并在详情页加"清除此漫画缓存" |
| 阅读器一直转圈不报错 | 没有超时处理 | 15 秒看门狗 → 显示错误 + 重试 |

## 四、编译与安装

```text
1. push 到 main
2. GitHub → Actions → 工作流 venerax-ios（约 12 分钟）
3. 打开该次运行的页面 → 底部 Artifacts → 下载 IPA
4. 装到设备上（自签 / 侧载按你自己的方式）
```

工作流会自动把构建日志作为 `ios build log [skip ci]` 提交回 `main`，所以本地推送前先 fetch/merge。
